# 04: 完成 HeroUI 看板、复习与测验

**What to build:** 学习者在两种主题下查看并导出学习记录、完成到期卡片评分、选择知识点和题型生成测验并提交答案；各流程使用统一的 HeroUI 基础控件，保留原有反馈和业务请求。

**Blocked by:** 02 — 完成 HeroUI 工作区导航与进度。

**Status:** ready-for-agent

依据规格《统一前端 HeroUI 基础控件与浅色/深色主题验收》。本任务可以在工作区任务完成后独立实施，不依赖路线控件、资料库或配置面板的迁移。

- [ ] 学习看板刷新、重试及导出入口使用 HeroUI，导出继续请求原有格式与端点，不改变学习数据或增加导出协议。
- [ ] 指标、状态分布、热力图及日报在浅色和深色模式下可读；热力图数据有文字说明，不只依靠颜色或透明度传达含义。
- [ ] 复习刷新、查看/隐藏答案和四档评分使用 HeroUI，保留正反面文本、当前无到期卡片和失败重试行为。
- [ ] 复习提交有明确加载反馈且不会重复评分，成功进入下一张卡片并按既有行为隐藏答案。
- [ ] 测验知识点、题型选择、数量输入、选项、答案文本域及操作按钮使用 HeroUI，选择器支持键盘选择和长文本展示，空知识点场景具有明确提示。
- [ ] 保留知识点选择校验、题目数量范围、请求内容、题目顺序、答案提交、反馈与下一题流程；已提交与加载状态正确限制重复操作。
- [ ] 正确/错误反馈和掌握度有文字说明；选项已选、空内容、读取中、禁用、错误与反馈区域在两种主题下可辨。
- [ ] 主题切换不清空当前复习状态、测验选择、当前题目、答案或反馈，也不触发额外请求和中断提交。
- [ ] 在 API 客户端处模拟数据，真实渲染 HeroUI，验证看板读取/重试与导出目标、复习评分后进入下一张、知识点与题型选择、测验提交及下一题，以及相关禁用与失败反馈。
- [ ] 完成真实浏览器浅色、深色及往返切换验收，覆盖长卡片/题目、窄屏布局、选择器浮层、键盘焦点和错误状态，记录证据。
- [ ] 更新三个模块的控件来源和主题记录，只清理本任务已无调用方的控件样式；类型检查、完整前端测试和静态生产构建通过。
